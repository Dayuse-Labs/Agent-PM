- decision · major · Q03: how homonym options map to fields. `label` copies the per-label formula of `geo_resolver._clarify_question` (rebuilt in `geocode_tool._option_label`), and a test checks that each label appears verbatim in the text question. `city` is the candidate's bare name, and `subject` is `echo_city`. - decision · minor · Q03: this narrows the earlier homonym mapping. A candidate with no name is now always left out, whatever its context, and `_option_label` no longer falls back to `place_name`. ## Q06

- decision · minor · Q06: §3 gave no defaults for some fields, so Q06 chose them. `carryover` defaults to "keep", which is today's geocode_location fill from profile_in, so an omitted value changes nothing. `relation` defaults to "in". `Place.kind`, `Exclusion.kind` and `Ambiguity.reason` default to null, and a null reason means no ambiguity. The task required a default on every field, and these are the most conservative choices. Q07 already maps any kind other than `city`/`hotel` to `zone`, does not apply `carryover` (S-L5) and maps only `city_needed`, so the defaults fit its mapping. No contract between tasks changes.
- decision · minor · Q06: every GeoIntent model is frozen (ConfigDict frozen=True). §3 did not ask for this. It makes `GeoIntent()` safe as a shared parameter default, which is the only declaration form ADK 2.4 reliably converts. Q07 must use `model_copy(update=...)` to correct an intent. Any in-place write fails loudly in Q07's own tests, so there is no silent risk and the field set is unchanged.
- decision · major · Q06: the GeoIntent schema has no ISO alpha-2 pattern on `country_named`, `places[].country`, `city.country` or the region strings. The format is only stated in the descriptions, because ADK validates the argument all-or-nothing and one pattern miss would drop the whole intent. Validation moves to Q07, but no criterion of Q07 covers it. Today `country_code` reaches the hard Mapbox `country` filter only lower-cased (`mapbox_client.py:133/175`), with no `_iso2` check. A value like "France" or "USA" in `country_named` would therefore become a malformed hard filter. The Q06 docstring adds a related point: an argument that fails validation reaches the tool as a raw dict, not rejected.
- deviation · minor · Q06: the task's ADK pointers (`_function_parameter_parse_util.py:169-178`, `:496-497`) describe ADK's legacy declaration path. ADK 2.4 actually builds the declaration through JSON_SCHEMA_FOR_FUNC_DECL (`_function_tool_declarations.build_function_declaration_with_json_schema`), which is experimental but on by default. LiteLLM receives `parameters_json_schema` unchanged. The legacy path would drop the field descriptions and `maxItems`. A Q06 test locks that the JSON-schema path is enabled, so an ADK upgrade that turns it off fails in CI. This corrects the task's context and changes no contract.
